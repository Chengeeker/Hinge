# UU 远程交互调研与 Hinge 差距（2026-10-29）

本轮仅调研、对照源码和保存设计依据，未修改产品代码或重建安装包。公开文档描述不等于当前 Android 版本实测；iOS 版本记录也不能自动视为 Android 行为。排除仿官网、下载站软文、无依据延迟数字，以及与官方说明矛盾的竞品横评。

## Hinge 当前源码与优先改进

查阅 android/lib/app/touchpad_screen.dart、desktop_video_view.dart 和现有验收表。当前普通桌面输入主要是相对位移；单指轻点左键，双指轻点右键，双指重心位移发滚轮，双击后按住拖拽。画面缩放要手动切到单独模式。Windows 光标目前合成进视频，Android 无独立指针层。

### 优先一：明确输入模式与状态反馈

- 侧栏提供“直接触控 / 鼠标指针”，清楚显示当前模式，并记住设备偏好。游戏视角作为独立操作状态。
- 直接触控模式需要绝对坐标协议及黑边、缩放、裁剪后的坐标逆映射；触点在黑边时不注入。不要把现有相对位移简单改名成触控。
- 指针模式继续保留触控板习惯；将按住拖拽、左右键按下等状态显示出来，进入拖拽提供一次触觉确认。退出、取消、切换模式、断线必须释放按键。
- 常用右键和拖拽提供可见操作入口，减少必须背诵“双击按住”的依赖。长按拖拽与长按右键只能按模式明确分工，不能同一手势同时触发。

### 优先二：缩放与滚动的手势仲裁

- 目标是在普通操作中双指平行移动滚动，双指距离变化缩放；放大后的画面平移需明确入口或手势。
- 两指落下先观察意图，超过阈值才锁定滚动或缩放；一旦锁定，本次手势不切换用途。缩放期间禁止误发鼠标/滚轮，保留当前缩放开关作为明确的替代入口。
- 以上是对 Hinge 的设计建议，不能写成已证实的 UU 内部识别算法。

### 优先三：光标反馈与视频分离

- 增加受认证会话绑定的光标坐标、形状、热点、可见性与序号消息；Android 单独画指针。
- 可对本机触控位移先做显示反馈，再用服务器确认位置校正；物理鼠标移动、多屏边界、裁剪和切换模式都需统一处理。不能只画一个与电脑位置脱节的假光标。
- 协商此能力后服务器停止视频内叠画，旧端继续视频内绘制，避免双光标。隐藏指针的游戏视角与普通桌面的“指针常驻”不能混成一条全局规则。
- 此项减少等待视频回程的指针观感延迟，不代表画面端到端延迟已解决。

### 优先四：地图/背包与游戏视角切换

- 视角模式按住左/右/中键滑动可按预设配置；提供右半屏控制区和独立 X/Y 灵敏度。
- 打开地图/背包需要可切换到可点击、可拖地图的指针/直接触控状态；回到游戏恢复视角。自动检测只作为辅助，须保留手动切换，因为隐藏光标不必然等于游戏锁定。
- 纯触控板页面已有用户定义的双指拖拽行为必须保留；桌面滚动手势、游戏拖拽与虚拟按钮多指不能相互抢指针。

### 后续：观看、外设与键盘

- 观看模式禁止输入；键盘提供 Esc/Tab/Ctrl/Alt/Win、F 区、方向键及可见的修饰键按下状态；先补常用组合键，再扩展完整外设。
- 横屏主体维持完整桌面比例，侧栏控制少量常用项；工具栏和交互区避开刘海/挖孔，键盘出现不重连桌面。
- 每项验收使用具体任务：点小文件图标、打开右键、拖窗、缩放后点击、地图拖到传送点、多指走动同时转视角；记录误触、卡键和指针偏差，而不只检查按钮存在。

## 技术证据边界

本轮没有找到能验证官方当前客户端全部内部实现的公开资料。H.265/AV1、WebRTC、拥塞控制、GPU 零拷贝或所谓最低延迟，不能仅凭宣传或第三方兼容实现认定为官方方案。交互改进先解决输入语义、反馈和手势冲突，媒体优化继续以 Hinge 自身采集/编码/网络/解码/呈现测量为依据。
